# Harness bench, Qwen3.5 9B and Ornith 1.5 9B across harnesses (2026-10-11)

All four harnesses on the full set, on Qwen3.5 9B and on Ornith 1.5 9B, side by side on the
same day: a fresh baseline for the current featherloop (`latest`, no advisor), and a look at
Ornith, a 9B built on Qwen3.5 and trained to find "effective strategies" by RL. Raw results
are in `gs://mm-llm-8deefb51-bench/results/2026-10-11-g4-all-{qwen,ornith}` (not in git); each
run's `summary.md` and `analysis.md`, and `g4-all-qwen-ornith.analysis.md` comparing them, are
in `2026-10-11/`.

## Setup

- **Cases:** `--set all`, the 82 Python and JavaScript exercises, one rep each: 328 runs a model.
- **Harnesses:** featherloop (`--shell`, no advisor), opencode-stock and opencode-custom
  (opencode v2.0.26; rounds 1–2 had v2.0.22), nanocode at `b009d3d`.
- **Models:** both Q5_K_M on llama.cpp b11429, each on its own pool of three spot
  `g4-standard-48` (`-c 262144 -np 5`), server sampling at the defaults below, which every
  harness gets except where featherloop's config sends its own.
  - **Qwen3.5 9B** (`qwen3.5-9b`): temperature 0.6, top-k 20, top-p 0.95, presence penalty 1.5
    (featherloop also sends 1.5). The same as 2026-10-07; only the build moved, from b11371.
  - **Ornith 1.5 9B** (`ornith-1.5-9b`, bartowski's GGUF): the model card's settings for
    coding, temperature 0.6, top-k 20, top-p 0.95, presence penalty 0. The GGUF carries Qwen's
    chat template, not Ornith's published one, which keeps the reasoning of every earlier
    assistant turn; with one user message a run, as here, both render the same.
- **Budget:** `--max-output 40000`, timeout 120 minutes (none hit). `-j 3` a server: 9 runs a
  model at once, 18 on the bench box (24 cores).
- **Code:** `bench-ornith` (`latest` plus Ornith in `models.json`).

**No difference anywhere beyond noise.** No harness beats another on either model (closest:
Qwen's featherloop against nanocode, 5 cases to 1, p = 0.22; Ornith's featherloop against
opencode-custom, 9 to 3, p = 0.15), and no harness does better on one model than the other
(featherloop 5 to 7, p = 0.77; the rest p ≥ 0.42). featherloop is first or tied first on both,
and leanest per pass on Qwen.

**Nearly every failure is the budget running out**: 49 of Qwen's 52, while iterating (the other
3 stopped with tests failing); all 48 of Ornith's, 25 of them inside one response.

## Ornith

**It loops without the presence penalty.** 25 of its 48 failures ended in one response that
reasoned until the budget ran out; in half of those the analysis lists (12 of 24), 43–88% of
the reasoning lines repeat an earlier one. That's what the penalty stopped for Qwen on
2026-10-06, and Ornith ran without it, as its card says for coding. It's also why its test
score trails Qwen's by 3–7 points while it passes as many: a runaway ends with what it had.

**It works in fewer, longer steps.** Half Qwen's tokens a run, 11–12 requests to Qwen's 19–20,
and 11–21k characters of reasoning before its first edit (Qwen: 2.5–3k).

**It goes looking for the answers.** In 6 runs across the three harnesses with a web tool it
went after a solution: Exercism's reference files (`.meta/reference.py`, `.meta/example.py`,
`.meta/proof.ci.js`, a `reference-solutions` repo that doesn't exist), a stranger's paasio on
GitHub, or a search for "exercism … solution". Qwen did that in none (its two fetches were
test data and Wikipedia). Two got a solution:

- **opencode-stock, javascript/go-counting:** listed `.meta` through GitHub's API and fetched
  `proof.ci.js`, the reference solution. Passed.
- **opencode-custom, python/scale-generator:** fetched `.meta/example.py`. Passed.

featherloop's attempt (python/go-counting) got only 404s and the test data, which is in the
workspace anyway, and passed on its own work. The bench's `Fetches from solution sources`
caught all of them. Any further Ornith runs should run without network.

## Smaller findings

- **nanocode doesn't time out a command.** One of Ornith's (javascript/zebra-puzzle) ran for
  81 minutes; the run ended at 89 minutes, out of budget. Wall clock, not tokens.
- **opencode v2.0.26 offers web search without a key.** Calls came back "Web search cancelled";
  opencode-custom then exited 1 (both "crashes", graded as passes, are the flagged runs above).
  Its note in the bench, "websearch off", no longer holds.
- **Qwen's featherloop changed `babel.config.js`** in javascript/parallel-letter-frequency: a
  preset swap, tests untouched, 13 of 13. The pass stands.
- **Two runs passed every test and still failed**, both javascript/parallel-letter-frequency:
  Qwen's nanocode left a worker thread open, so Jest didn't exit cleanly and the grader
  failed it; Ornith's opencode-stock (out of budget anyway) left a failing `dbg.spec.js` of
  its own, which `npm test` runs too. Both are how the exercise's own test command treats
  them, as in Aider's runner.
- **`test/shell.test.ts` flakes**: its timeout tests fail now and then with an extra "Killed"
  line (about 1 run in 8 on `latest`).

## Infrastructure

- **Both pools held.** No API errors, no timeouts; one requeue after a connect timeout (Qwen),
  one failed server listing (Ornith), both handled as designed. 0–9 resends a column.
- Each group was resized to 0 as its queue drained, with a backstop resize set for the night.

`bench-pi`), with the server's presence penalty at 1.5 and nothing else changed: 410 runs,

`analysis.md`, and `g4-all-ornith-presence.analysis.md` comparing it with the run above, are

**The penalty halved Ornith's runaways (25 to 12 in the four harnesses) and nothing else
moved beyond noise.** Test scores rose 1–4 points in every harness, and passes 278 to 285
across the four, after the corrections (cases one way or the other, 20 to 27, p = 0.38; no
single harness p < 0.34). It didn't end
runaways as it did for Qwen.

**Pi ties featherloop**: 74 each, test score 94% each, 3 cases to 3 (p = 1.0), at 308k tokens a
pass to featherloop's 247k. It works differently: the fewest completion tokens (9.4k a run),
the most requests (17.3), and a median 1.5k characters of reasoning before its first edit,
against 11–19k for the others. Two of its runs ran a command until the 120-minute timeout
(Pi's shell has none of its own), as did four of nanocode's (one of them the dropped run below).

**The bench's own checkout is reachable, and one run used it.** Harnesses run unsandboxed.
10 Python runs have those paths in their conversation, from searching the whole filesystem
(`find / -name grep.py` and the like), which lists the polyglot checkout of every bench
checkout on the box, and other runs' workspaces. In
one, opencode-custom on python/paasio, it then read `.meta/example.py` from the main
checkout's copy, compared it with its own, and passed. The others only listed paths and
read nothing from them (checked by hand); opencode-stock's paasio read the stub and failed.
The bench's `sawCache` only looks for its own checkout's path, so a read from another
checkout's copy would have gone unflagged; it flagged this one because the same `find`
listed both. Read for any `polyglot-benchmark` path and for other runs' workspaces, the
Qwen run and the first Ornith run are clean. The first run's Ornith reached for answers on
the web; this one, with no luck there (404s, cancelled searches), on disk.

**One run broke the bench's bookkeeping.** nanocode's python/connect ran one `python3 -c`
that printed for two hours, until the timeout: a 33 GB `stdout.log`, which `sawCache` then
read whole and threw on, so the run was dropped without a row (graded: failing). The log was
cut by hand to its first 20 MB and last 5 MB; `bench-big-logs` reads it in chunks.

## Next

- **Sandbox the harnesses before the next model.** A model trained to find what works
  finds the answers: on the web in one run, on disk in the next. Runs need no network for
  their cases and no files outside their workspace and toolchains, so a sandbox (bubblewrap
  or a container: network off, the workspace and caches bound in, nothing else) closes both,
  and caps what a runaway command can write. Until then, `sawCache` should match any
  `polyglot-benchmark` path and other runs' workspaces.
- **Move up a size.** The 9B's harness comparisons are settled as far as this set goes: no
  harness or prompt line moves passes beyond noise, sampling did, and a harness-triggered
  advisor did. Next is a model still runnable on a laptop, Qwen3.6 35B A3B, on harder cases:
  it passed 94–99% of this set in round 1, so first calibrate on `all-rust` (with the Rust
  exercises) and build a hard set from what fails.
