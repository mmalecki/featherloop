# Harness bench, a harness-triggered advisor at the repeat signal (2026-10-08)

featherloop on the 9B's informative hard cases: when the repeat sensor says a command's
output repeats, the loop asks Sonnet, itself, for advice, and passes it on as the user.
Does that make the 9B pass more? Raw results are in
`gs://mm-llm-8deefb51-bench/results/2026-10-08-g4-hard-9b-mid-NV` (not in git); the run's
`summary.md`, `analysis.md` and `advice.md` are in `2026-10-08/`.

## Setup

- **Cases:** `--set hard-9b-mid`, 9 cases, 10 reps (90 runs per arm).
- **Model:** Qwen3.5 9B Q5_K_M, llama.cpp b11371, three spot `g4-standard-48`, presence
  penalty 1.5; `--max-output 40000`.
- **Code:** `advisor-on-repeat` (21abb67, on `nudge-on-repeat`). When a tool result carries
  the repeat sensor's note, the loop calls the `subagent` tool itself: the `advisor` agent,
  with the conversation (`transcript: true`) and the task "The agent you advise is going
  round in circles: its last command's output repeated an earlier one. From the task, what
  it has tried and the code, say what it's missing and what to try next, in a few
  sentences. Don't write the solution." Its reply goes to the 9B as the user, after the
  nudge of 2026-10-07: "…Before your next command, say what you expected, what you got, and
  what you'll do differently. A stronger model looked at what you've done so far. Its
  advice: …". At most 3 times a run. With no advisor on offer, the nudge alone.
- **Arms**, one bench, interleaved (10:23–12:40 UTC), `-j 4`:
  - **N:** `featherloop`, no advisor: the nudge alone.
  - **V:** `featherloop-advisor`, with `--advisor claude-sonnet-5-5` (effort high): the nudge
    and the advice.

  The arms run the same code, and are the same up to a run's first repeat; after it, they
  differ only in the advice.
- **Readouts, set before the run:** test score and passes, V against N (stratified
  permutation; two like arms of 90 land within ±5.6 points of score); then how the runs
  that got advice did; then whether the advice gave away code.

## Results

| | N: nudge | V: nudge + advice | p |
|---|---:|---:|---:|
| Passed | 45/90 (50%) | **73/90 (81%)** | < 0.001 (wins 8 vs 36) |
| 95% interval | 40–60% | 72–88% | |
| Test score | 84% | **95%** | < 0.001 (+11.4 points) |
| Runs that hit a repeat | 42 | 51 | |
| … of which passed | 16 (38%) | **44 (86%)** | |
| Runs that never did, passed | 29 of 48 (60%) | 29 of 39 (74%) | |
| Advice messages / run | 0 | 0.82 | |
| Advisor cost | – | $5.56 ($0.075 an advice, $0.06 a run) | |
| Tokens / pass | 1806k | 953k | |
| Out of budget, iterating | 44 | 17 | |
| API errors | 0 | 0 | |

**The advice works.** 73 passes against 45, and 95% of tests against 84%: the largest
difference the bench has measured, well past its noise (p < 0.001 for both). Of the runs
that got stuck repeating, 86% passed with advice, against 38% with the nudge alone. Up to
a run's first repeat the arms are the same, so which runs hit one is chance, and among
those that did, the advice is the only difference.

**It works where the 9B is stuck for an idea.** `python/connect`, at 1 pass in 10 without
it, passed 8 with it; `python/react` 2 to 8; `python/transpose` 5 to 10; `python/book-store`
6 to 10. The smoke run's advice on `connect` shows how: "This board is a parallelogram …
the neighbor offsets are the same for every row, with no parity check," with the offsets
worked out from the 9B's own debug output. Three nights of method changes (prompt lines,
edits over rewrites, the nudge) moved what the 9B did and not what it got right; an idea
from a stronger model at the moment it's stuck is what it lacked.

**The runs that never repeated show the noise.** They're the same code in both arms, and
passed 60% against 74%: a gap like that is chance at this size. The 81% against 50% isn't.

**It's cheap.** Sonnet mostly answered from the conversation alone, in one turn: 98
requests for 74 advices, 21 of them reading files first; a median 24k tokens in (the
transcript, cached) and 764 out, 7.5 seconds. That's $0.075 an advice and $0.06 a run:
$0.20 for each pass it added. The 9B's own tokens per pass halved (953k against 1806k): advised runs
stop iterating sooner.

**What the advice gives away.** None of the 74 messages has code (no fenced block or
code-like line). But they're specific: the exact neighbour offsets on `connect`; on
`book-store`, "Groups of 2 and 3 are never formed, which is why `test_two_different_books`
and `test_three_different_books` fail," and "You've rewritten the same 'pick counts of
5-groups and 4-groups, then lump the leftovers into one group' heuristic four times." It's
the idea, and where the 9B went wrong, not the code; a gentler advisor ("the process and
the general idea") may give less away, and help less.

## Notes

- **Coverage:** only runs that repeat a command's output get advice: 51 of V's 90. Runs
  stuck without repeating (iterating on new variants each time) never trigger it; another
  trigger (the same tests failing N test runs in a row) could reach them.
- **Measuring it:** the summary's "Advisor calls / run" counts calls the model makes, so it
  reads 0 here; the advisor's requests and cost are metered on its own proxy and are right.
  `advice.md` counts the advice messages from the transcripts.
- **Infrastructure:** no API errors, requeues, refusals, lost servers or timeouts; 5–8
  requests resent per arm. Results synced to the bucket as they came; the instance group
  was resized to 0 at 12:40 UTC.
